# Образы дисков

Bootimus умеет снимать образ диска клиента и разворачивать этот образ обратно на один клиент или на всех участников группы клиентов. Для этого он в автоматическом режиме управляет встроенным инструментом **Clonezilla Live**, так что порядок работы знаком по FOG: поставить задание в очередь, дать машине загрузиться по PXE и посмотреть результат в админ-панели.

## Как это работает

1. Вы ставите в очередь задание **capture** или **deploy** для клиента из админ-панели или через API. Каждое задание несёт случайный токен.
2. При следующей PXE-загрузке клиента меню сразу переходит к пункту Clonezilla, собранному из ядра, initrd и squashfs инструмента Clonezilla.
3. Clonezilla получает от Bootimus короткий скрипт задания (`/diskimage/job?token=…`), монтирует хранилище образов по NFS, запускает `ocs-sr` и отчитывается на `/diskimage/callback`.
4. Снятие образа по завершении выключает клиент. Развёртывание перезагружает его в свежевосстановленный диск.

Задание выдаётся только тому MAC-адресу, для которого оно поставлено в очередь, а завершённое, неудачное или отменённое задание больше никогда не выдаётся.

## Требования

- **Инструмент Clonezilla**: скачайте и включите его в разделе **Tools**. Страница образов дисков сообщает, если его нет.
- **NFS-сервер**: запустите Bootimus с `--nfs-enabled` (или `nfs_enabled: true` в `bootimus.yaml`). Clonezilla нужна доступная для записи шара, куда сохранять, и встроенный NFS-сервер предоставляет её без дополнительных пакетов.
- **Загрузка ядром** для клиента (по умолчанию). Образы дисков не работают с sanboot и memdisk.
- Порт `2049/tcp` (или настроенный `--nfs-port`) должен быть доступен с клиентов, помимо обычных портов TFTP и HTTP.

## Снятие образа диска

1. Откройте **Disk Images** и нажмите **Capture Disk…** либо нажмите **Capture Disk** в строке клиента в разделе **Clients**.
2. Выберите клиент, задайте имя образа (строчные буквы, цифры, точки, дефисы и подчёркивания) и выберите диск. По умолчанию `sda`; `nvme0n1` и подобные тоже работают, а `auto` берёт первый несъёмный диск с возможностью записи, который найдёт Clonezilla.
3. При желании отметьте **Send Wake-on-LAN now**.
4. Перезагрузите клиент (или пусть это сделает magic packet). Он загрузит Clonezilla, сохранит диск и выключится.

Clonezilla выполняет `ocs-sr -q2 -j2 -z1p -i 4096 -sc savedisk <name> <disk>`: partclone там, где это возможно, включая скрытые данные между MBR и первым разделом, многопоточное сжатие gzip, разбиение на тома по 4 ГиБ.

Пока идёт снятие, образ показывается как **capturing**. Когда клиент сообщает об успехе, образ становится **ready** и записывается его размер. Если `ocs-sr` завершается с ошибкой, образ помечается как **failed**, а частичные данные удаляются.

**Через API**:
```bash
curl -X POST -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"mac_address":"aa:bb:cc:dd:ee:ff","name":"win11-lab","description":"Lab build, Oct 2026","disk":"sda","wake":true}' \
  http://localhost:8081/api/disk-images/capture
```

## Развёртывание образа

1. Нажмите **Deploy** рядом с готовым образом, **Deploy Image** в строке клиента или **Deploy Disk Image to All…** в массовых действиях группы клиентов.
2. Выберите цель (один клиент или группу клиентов), перезаписываемый диск и нужно ли отправлять Wake-on-LAN. Групповые развёртывания учитывают широковещательный адрес WOL и задержку между клиентами, заданные для группы.
3. Подтвердите. Всё содержимое целевого диска будет заменено.

Clonezilla выполняет `ocs-sr -g auto -e1 auto -e2 -r -j2 -scr restoredisk <name> <disk>`: таблица разделов пересоздаётся из образа, разделы увеличиваются, чтобы заполнить больший диск, GRUB переустанавливается там, где он был в образе, и по завершении клиент перезагружается.

Каждый участник группы получает своё задание, так что можно наблюдать, как они завершаются один за другим. Клиент, у которого уже есть активное задание, пропускается и перечисляется в ответе.

**Через API**:
```bash
# One client
curl -X POST -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"mac_address":"aa:bb:cc:dd:ee:ff","image_id":3,"disk":"sda"}' \
  http://localhost:8081/api/disk-images/deploy

# Every enabled member of client group 2, waking them as it goes
curl -X POST -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"client_group_id":2,"image_id":3,"disk":"auto","wake":true}' \
  http://localhost:8081/api/disk-images/deploy
```

## Задания

Таблица **Capture and Deploy Jobs** показывает каждое задание с его состоянием:

| Состояние | Значение |
|-----------|----------|
| `pending` | В очереди; ждёт PXE-загрузки клиента |
| `running` | Clonezilla получила скрипт задания и работает |
| `completed` | Клиент сообщил об успехе |
| `failed` | Не удалось монтирование или `ocs-sr`; причина в колонке сообщения |
| `cancelled` | Отменено из панели или через API |

Ожидающие и выполняющиеся задания можно отменить. Отмена снятия образа удаляет записываемый образ. У клиента может быть только одно активное задание одновременно.

Предпросмотр меню загрузки (**Preview Menu** в строке клиента) показывает пункт загрузки Clonezilla, пока задание активно, так что это быстрый способ проверить, что сделает клиент.

Завершённые задания вызывают события вебхука `disk.capture_completed`, `disk.capture_failed`, `disk.deploy_completed` и `disk.deploy_failed`, если эта опция включена в **Settings → Webhook**.

## Где хранятся образы

Образы представляют собой обычные каталоги образов Clonezilla в `<data-dir>/disk-images/<name>/`, поэтому их можно просматривать, копировать в другое место или восстанавливать вручную с любой флешки Clonezilla Live. Снимаемые в данный момент образы записываются в `<data-dir>/disk-images/.staging/<token>/` и перемещаются на место, когда клиент сообщает об успехе.

Образы дисков велики, поэтому следите за карточкой **Housekeeping** в разделе **Settings**, где показано, сколько места занимает каждый элемент верхнего уровня каталога данных. Бэкапы из админ-панели пропускают каталоги `isos` и `tools`, но включают всё остальное, так что удалите ненужные образы дисков перед скачиванием бэкапа.

## Доступность в сети

Clonezilla монтирует хранилище образов по NFS v3 без аутентификации, так же как работают FOG и DRBL. Bootimus ограничивает то, что открывает эта шара:

- обычный экспорт для загрузки (`isos/`) и корень образов дисков доступны только для чтения;
- задание снятия образа получает собственный экспорт с записью по пути `/disk-images/.staging/<token>`, который существует только пока задание активно и который нельзя угадать без токена;
- отдельные каталоги образов нельзя смонтировать напрямую; развёртывания монтируют корень образов только для чтения.

Держите сеть загрузки в сегменте, которому доверяете, как и положено для PXE.

## Диагностика

**Задание остаётся в pending.** Клиент не загружался по PXE после постановки задания в очередь, либо загрузился, но Clonezilla не включена, и Bootimus выдал обычное меню. Проверьте **Tools**, затем **Preview Menu** в строке клиента.

**`nfs_mount_failed` в колонке сообщения.** Клиент не смог смонтировать шару. Убедитесь, что задан `--nfs-enabled`, что порт NFS доступен из подсети клиента и что `--server-addr` — это адрес, до которого клиент может достучаться.

**`no_disk_found` при `disk=auto`.** Clonezilla не нашла несъёмный диск с возможностью записи. Укажите имя устройства явно.

**`ocs-sr_exit_N`.** Сбой в самой Clonezilla. Клиент показывает вывод Clonezilla 30 секунд перед перезагрузкой; обычные причины — снятие образа диска со смонтированной или повреждённой файловой системой либо развёртывание на диск меньше образа.

**Образ показывается как failed.** Ничего не отменяйте; удалите его на странице **Disk Images** и снимите образ заново.
